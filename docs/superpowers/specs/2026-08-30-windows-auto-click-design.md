# My Window Auto Click — Windows 裁剪改造设计

日期：2026-08-30

状态：已获方向确认，等待书面规格复核

上游底座：`Agzes/FluAutoClicker` `next` 分支，基线提交 `e37448f536aea18350dfbcbd4fef90bca218341d`

## 1. 背景与结论

本项目从 FluAutoClicker 派生，面向单一用户的 Windows 10/11 本地自动输入场景。产品工作名为 **My Window Auto Click**。它不是只做鼠标点击，而是保留并收敛为三个能力：鼠标连点、键盘连按、键鼠宏录制与循环回放。

选择直接裁剪上游的原因是它已经具备 Tauri 桌面外壳、鼠标和键盘执行器、低级全局录制、宏动作模型、次数/时长/无限循环、全局热键及预设系统。改造重点不是重新制作这些功能，而是删除无关平台能力、修复停止与输入释放边界、提高预设可靠性，并把交互简化成自用工具。

项目继续遵守上游 MIT 许可证。发行物和源码保留上游版权与许可证声明，不使用其他候选仓库的受限代码；其他仓库只作为行为与测试参考。

## 2. 目标

### 2.1 核心目标

- 在 Windows 10/11 上提供可携带运行的桌面应用。
- 重复鼠标左键、右键或中键，可选当前位置或固定坐标。
- 重复普通键、功能键、导航键和带修饰键的组合键。
- 每种执行模式都支持三种停止策略：指定次数、指定持续秒数、手动停止。
- 默认按 `F8` 启动或停止当前选择的模式，并允许用户重新绑定。
- 录制键盘、鼠标按键、滚轮及动作间隔，保存为可命名预设并循环回放。
- 停止、异常、退出或达到截止时间时，及时释放本程序仍保持按下的键或鼠标键。
- 全部设置和录制数据只保存在本机，不需要账户、云端或运行时网络访问。

### 2.2 非目标

- 不提供反作弊绕过、规避检测、自动瞄准、抢票、考试或考勤自动化能力。
- 不控制管理员权限高于本程序的窗口，也不默认请求管理员权限。
- 不支持 Linux、macOS、移动平台或后台驱动级输入。
- 不加入图像识别、OCR、条件分支、脚本语言、定时任务或多设备同步。
- 第一版不提供多个宏并行播放；任何时候只允许一个执行器运行。

## 3. 产品结构

主界面保留三个一级模式：

1. **鼠标连点**：按钮、点击方式、频率、位置和停止策略。
2. **键盘连按**：目标键、可选修饰键、按下方式、频率和停止策略。
3. **录制预设**：录制、动作列表、回放速度、停止策略和预设管理。

托盘能力保留，用于显示状态、打开窗口、启动/停止和退出。界面默认中文，英文作为回退语言。其余语言资源移除，避免后续每次修改都维护九套文案。

应用启动后默认处于停止状态，不自动执行任何输入。上次选择的模式和设置可以恢复，但播放必须由用户显式触发。

## 4. 裁剪范围

从上游移除以下能力及其界面、命令、配置和依赖：

- Linux `/dev/uinput`、Linux 权限修复及 Linux 构建说明。
- Mouse Jiggler 和 O-Zone 等防休眠功能。
- CLI 启动、停止、切换和无界面执行入口。
- 自动启动配置。
- 在线更新检查、预发布通道及相关网络入口。
- 社区、网站和推广入口。
- 除中文和英文以外的本地化文件与选择项。

保留 Tauri + Rust 后端与 TypeScript/Vite 前端，不在本阶段迁移到 C#。保留 Windows 托盘、主题基础、全局热键、预设导入/导出和窗口置顶等对自用有价值的能力。

## 5. 运行状态模型

应用使用单一顶层状态机：

- `Idle`：没有执行或录制。
- `Recording`：只允许录制，不允许点击、连按或回放。
- `RunningMouse`：鼠标连点运行中。
- `RunningKeyboard`：键盘连按运行中。
- `PlayingMacro`：宏回放运行中。
- `Stopping`：取消已发出，等待清理并释放本程序持有的输入。
- `Error`：已完成清理并向界面报告错误，之后回到 `Idle`。

所有启动入口都经过同一个协调器。协调器拒绝重入，防止两个后台任务同时发送输入。模式切换和修改关键设置只在 `Idle` 时允许。

## 6. 热键规则

- `F8`：默认启动/停止当前选择的执行模式，可配置。
- `Ctrl+Shift+R`：默认开始/停止宏录制，可配置。
- `F12`：固定紧急停止，不可配置，始终优先于普通执行逻辑。

普通启停键和录制键不能相互重复，也不能与 `F12` 冲突。键盘连按目标若与普通启停热键完全相同，设置页拒绝启动并提示用户修改其中一个。

录制器排除录制开始/停止热键的边缘事件以及 `F12`。热键捕获界面临时暂停已注册的普通热键，保存成功后再恢复。紧急停止通道不随普通热键暂停而失效。

## 7. 输入与停止语义

### 7.1 鼠标和键盘计数

- 一次鼠标计数代表完整的按下和抬起；双击模式仍算一个执行周期。
- 一次键盘计数代表完整的按下和抬起；组合键计为一次执行周期。
- 宏的“一次”代表动作列表从头到尾完整执行一次。

### 7.2 三种停止策略

- `UntilStopped`：持续运行，直到 `F8`、`F12`、界面停止或退出。
- `RepeatCount(n)`：完成恰好 `n` 个执行周期后停止。
- `Duration(deadline)`：使用单调时钟计算硬截止时间；到期时即使正在等待或保持按键，也进入停止清理。

宏在按时长模式下可能在某次迭代中途结束，这是硬截止时间的预期语义。按次数模式只在完整迭代结束后增加计数。不同循环之间不自动增加额外延迟；如果用户需要间隔，应在录制末尾保留或手工增加等待动作。

### 7.3 可中断等待

当前上游使用普通 `sleep`，长等待和长按不能及时响应停止。改造后所有等待都必须同时监听：

- 取消信号；
- 持续时间截止信号；
- 正常等待完成。

Rust 实现使用可取消令牌或广播通道配合 `tokio::select!`。停止请求发出后，目标是在正常系统负载下 100 毫秒内进入输入释放阶段；不保证目标程序在同一时间内处理已经送达的输入。

### 7.4 Held-input 跟踪与释放

执行器只跟踪本程序通过回放实际按下的键和鼠标键。每次成功发送 `Down` 后登记，每次成功发送 `Up` 后移除。正常完成、用户停止、截止时间、发送错误、任务 panic 和应用退出都走同一清理路径，逆序释放仍登记的输入。

清理器不得枚举并释放用户真实按住但本程序没有发送的键，以免破坏用户正在进行的输入。

## 8. 宏录制模型

录制事件至少包括：

- 键盘 `Down` / `Up`，保留左右修饰键能够表达的组合关系。
- 鼠标左、中、右键 `Down` / `Up`。
- 鼠标滚轮。
- 动作间隔。
- 可选的鼠标移动轨迹。

鼠标移动默认关闭，因为高频轨迹会迅速增大文件并降低编辑可读性。用户可以在录制设置中选择开启合并后的平滑轨迹。第一版从界面移除“原始高频轨迹”选项，但为了兼容上游旧预设，回放器仍可读取已有的 `RawMove` 动作。

录制时使用单调时间源计算相邻事件间隔，避免系统时钟校准导致负时间或跳跃。小于阈值的间隔可以合并，但键盘或鼠标的 `Down` / `Up` 顺序不能被压缩掉。按键自动重复事件去重，真实长按以一对 `Down` / `Up` 和中间时长表达。

录制和回放互斥。回放期间录制钩子即使常驻也不写入事件，从而避免把程序注入的输入重新录入宏。

## 9. 预设与本地存储

一个预设包含：

- 稳定 ID、用户可修改名称、格式版本和更新时间。
- 当前模式。
- 鼠标连点设置。
- 键盘连按设置。
- 宏动作和宏录制选项。
- 三种模式各自的停止策略。
- 普通可配置热键；固定 `F12` 不写入预设覆盖项。

预设支持创建、复制、重命名、删除、切换、导入和导出。默认预设不能删除，但可以恢复默认值。

JSON 导入执行格式版本、字段类型、事件类型、数值范围和文件大小校验。单个导入文件上限为 50 MB；未知动作、非法时间、超出范围的坐标或计数会拒绝整个导入，而不是部分接受。

保存采用同目录临时文件、刷新落盘、平台安全替换和最后有效备份。写入失败时保留原文件并报告错误，不让内存中的新设置伪装成已保存。迁移逻辑必须保留读取上游现有 `app_config.json`、profile JSON 和 `macro.json` 的能力，第一次成功保存后再写入新版本格式。

## 10. 错误与权限处理

- 全局热键注册冲突：指出冲突热键并保持旧绑定有效。
- 输入钩子或输入发送失败：立即停止、释放 held inputs，并显示可操作错误。
- 目标窗口权限较高：提示以相同完整性级别运行，但不自动提权。
- 预设损坏：尝试读取最后有效备份；仍失败则进入安全默认配置，不自动覆盖损坏文件。
- 应用退出：先停止录制和执行任务，释放输入，注销热键，随后关闭窗口。

所有错误信息必须避免承诺能够绕过游戏、反作弊、管理员窗口或系统安全边界。

## 11. 测试策略

实现采用测试优先，重点测试纯状态与边界，不依赖真实桌面输入完成核心覆盖。

### 11.1 Rust 单元测试

- 状态机拒绝重入和非法转换。
- 次数、时长和无限停止策略。
- 长等待收到取消后立即返回。
- `Down` 成功、`Up` 缺失时的逆序释放。
- 发送动作失败、任务取消和退出时均执行清理。
- 录制 `Down` / `Up`、组合键、长按和自动重复去重。
- 热键事件从录制首尾排除。
- 单调时间差转换为等待动作。
- 预设校验、迁移、原子替换失败及备份恢复。

### 11.2 前端检查

- TypeScript typecheck。
- 静态 DOM smoke 检查。
- 中文和英文键集合一致性检查。
- 三个模式的停止策略界面映射。
- 热键冲突提示和运行中设置锁定。

### 11.3 构建与人工验收

- `npm run lint`
- `npm run build`
- `npm run test:rust`
- Windows Tauri release build。

当前基线中 lint 和前端 build 已通过。Rust tests 因本机 GNU Rust 工具链缺少 `dlltool.exe` 尚未启动测试二进制。项目统一采用 Tauri 在 Windows 上支持的 `x86_64-pc-windows-msvc` Rust 工具链和 Microsoft C++ Build Tools；安装这些系统级依赖前需要用户单独批准。不能把当前环境失败计为测试通过。

## 13. 完成标准

- 三个模式在 Windows 10/11 上均可由界面或 `F8` 启停。
- 指定次数、指定秒数和手动停止符合本设计语义。
- `F12` 能中断长等待或长按，并释放本程序持有的输入。
- 录制结果能正确重放组合键、长按、鼠标点击和滚轮。
- 命名预设重启后仍可加载，损坏写入不会破坏最后有效版本。
- 应用运行时不需要网络连接，不包含已裁剪功能的残留入口。
- 自动检查、Rust tests、Windows release build 和受控 smoke 都有真实成功证据。
- MIT 许可证和上游署名保留在源码与发行物中。
